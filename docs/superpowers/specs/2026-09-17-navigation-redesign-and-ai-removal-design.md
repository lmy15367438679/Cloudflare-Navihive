# Navihive 导航界面重构与 AI 功能移除设计

日期：2026-09-17

## 背景与目标

Navihive 当前已经具备导航、搜索、收藏、设置和分组排序等主要能力，但整体视觉仍偏功能拼装，部分渐变、阴影、悬浮控件与页面层级缺少统一规则。与此同时，AI 助手横跨前端、Worker、模拟 API 和配置初始化，增加了维护成本，但已不再属于产品目标。

本次改造包含两个目标：

1. 将界面重构为成熟、安静且高效的导航目录产品；
2. 从前端和 Worker 中彻底移除 AI 功能，同时不迁移或清理现有 D1 数据。

## 范围

### 包含

- 页面布局、侧栏、顶栏、搜索、分组标题和网站卡片的视觉统一；
- 浅色与深色主题的语义化颜色体系；
- 桌面端、移动端和触屏设备的响应式体验；
- 分组拖动入口、过程反馈、失败回滚和并发保护；
- AI 前端组件、API、类型、状态、默认配置和模拟实现的删除；
- Worker AI 路由、流式响应、设置、技能、限流和加解密逻辑的删除；
- AI 环境变量说明、初始化 SQL 插入项和相关文档的清理；
- 重复样式、无效导入和冗余状态的整理。

### 不包含

- D1 表结构变更；
- 删除线上 D1 中已经存在的 `ai.*` 配置记录；
- 新增数据库迁移；
- 更换现有 GitHub 托管和 Cloudflare 自动构建流程；
- 与导航体验无关的功能扩张。

## 视觉方向

采用“编辑目录 · 温和中性”方向。

### 设计原则

- **内容优先**：通过文字层级、间距和边界组织内容，减少装饰性渐变与发光。
- **稳定导航**：桌面端使用固定窄侧栏，使导航、收藏和设置入口保持稳定位置。
- **低干扰卡片**：卡片以轻边框和微弱层次为主，悬停反馈明确但不过度放大。
- **统一主题**：浅色与深色共用语义变量，组件不直接绑定具体色值。
- **克制动效**：仅为状态变化、拖动和菜单开合提供短促反馈，并尊重 `prefers-reduced-motion`。
- **渐进披露**：管理控件在需要时出现，浏览状态下保持安静。

### 页面结构

桌面端由固定窄侧栏和主内容区组成：

- 侧栏承载品牌、主页/导航、搜索或收藏入口以及设置；
- 主内容区顶部承载全局搜索和账户入口；
- 首屏说明保持简短，不使用大面积营销式 Hero；
- 分组按清晰的纵向节奏排列；
- 网站卡片根据可用宽度自适应列数。

移动端将侧栏收敛为紧凑顶栏或底部可达入口，网站卡片退化为单列或双列，确保触控目标尺寸不小于 44px。

## 分组排序交互

### 入口

- 拖动把手位于分组标题的操作区域；
- 桌面端仅在分组标题区域悬停或内部元素获得键盘焦点时显示；
- 触屏或无悬停能力的设备始终显示；
- 分组标题本身不承担拖动，避免影响文本选择与其他按钮点击；
- 把手具有可访问名称、可见焦点和适当的触控尺寸。

### 状态与持久化

- 拖动开始后突出当前分组，并显示明确的插入位置；
- 本地顺序先更新，再调用现有持久化接口；
- 保存期间锁定新的排序提交，避免请求相互覆盖；
- 保存成功后解除锁定；
- 保存失败时恢复拖动前顺序，并显示用户可理解的错误提示；
- 排序功能沿用现有数据结构，不增加 D1 字段或迁移。

## AI 功能移除

采用编译期完整移除，而不是功能开关或仅隐藏界面。

### 前端

- 删除 AI 助手组件以及所有入口；
- 删除 `App` 中 AI 开关、状态、默认配置和回调；
- 删除客户端 AI 设置、聊天、流式响应和技能相关方法；
- 删除 AI 专用类型、常量和默认提示词；
- 删除模拟 API 中对应数据和行为；
- 清理因 AI 功能产生的失效依赖和导入。

非 AI 业务中的“自动”功能或仅使用类似图标的功能不会按名称误删，必须根据实际业务语义判断。

### Worker

- 删除 AI 设置读写路由；
- 删除 AI 聊天和 SSE 流式输出路由；
- 删除 AI 技能与外部技能处理；
- 删除 AI 专用限流、校验、默认提示词和加解密帮助函数；
- 删除 AI 路由的认证例外；
- 从 Worker 环境类型和配置模板中删除 `AI_SECRET`。

### D1 边界

- 从 `init_table.sql` 中删除用于新部署的 `ai.*` 默认插入语句；
- 不执行删除语句；
- 不清理现有环境中的 `ai.*` 行；
- 不修改配置表结构；
- 旧数据将成为无代码读取的惰性数据，后续可通过独立迁移处理。

## 代码结构与冗余治理

- 建立少量稳定的主题变量：背景、表面、边界、主文字、次文字、强调色和危险色；
- 将分组标题、卡片和操作控件的重复视觉规则收敛到共享样式或复用组件；
- 保持业务状态靠近使用它的组件，避免将局部 UI 状态提升到 `App`；
- 删除仅为 AI 功能存在的 props 透传；
- 合并重复响应式判断和状态样式；
- 保持现有导航、搜索、收藏、登录、导入导出和设置功能行为兼容。

## 错误处理与兼容性

- 对排序保存失败提供回滚和消息提示；
- 删除 AI 路由后，对旧客户端请求返回常规 404，不增加兼容占位接口；
- 导入旧配置时忽略无法识别的 `ai.*` 字段，不因遗留数据阻断导入；
- 导出逻辑不再包含或特殊处理 AI 密钥；
- 保持现有认证和非 AI API 路由行为不变。

## 验证策略

本地验证保持精简，重点依赖 GitHub 与 Cloudflare 自动构建：

1. 运行格式检查、ESLint 和 TypeScript 生产构建；
2. 检查桌面、移动端、浅色和深色模式；
3. 冒烟验证导航、搜索、收藏、登录和设置；
4. 验证分组拖动、触屏入口、保存锁定和失败回滚；
5. 全仓搜索 AI 组件、路由、类型、环境变量与文档残留；
6. 推送 GitHub 后观察 Cloudflare 自动构建和部署结果；
7. 若 Cloudflare 失败，依据构建日志修正代码或配置，但不触碰 D1 数据。

## 验收标准

- 页面呈现统一、克制的成熟导航目录风格；
- 关键功能在桌面和移动端均可达；
- 分组拖动入口符合悬停、聚焦和触屏规则；
- 排序失败能够恢复原顺序；
- 前端产物和 Worker 中不存在可调用的 AI 功能；
- 新部署不会写入 AI 默认配置；
- 现有 D1 表结构与数据未被修改；
- 本地质量检查通过，Cloudflare 自动构建部署成功或给出明确的外部配置阻塞原因。
