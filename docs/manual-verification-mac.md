# Mac 手动验证教程（虚拟化 / 收藏 / 搜索 / 开发者选项）

针对 macOS 环境的验收步骤。覆盖：侧栏/搜索跳转分组、本地收藏置顶、
折叠展开后的高度重测、⌘K 全局搜索、开发者选项（帧率与日志）。

## 0. 环境准备

```bash
# 安装 pnpm（如未安装）
brew install pnpm          # 或 corepack enable

# 进入项目并启动开发服务器
cd ~/Desktop/code/Cloudflare-Navihive
pnpm install
pnpm dev
```

终端会输出 `Local: http://localhost:5173/...`，用 Chrome / Safari 打开该地址。
默认走 Mock API（`VITE_USE_REAL_API` 未设），可离线验证交互逻辑。

## 1. ⌘K 全局搜索（Mac 快捷键）

1. 打开页面后**不做任何操作**、侧栏处于收起状态，直接按 **`⌘` + `K`**。
2. 预期：**侧栏自动展开**，搜索框获得焦点并可直接输入（⌘K 现在由 App
   顶层以捕获阶段统一拦截，先派发「展开侧栏」再聚焦，不再把焦点塞进隐藏输入框）。
3. 也可用 **`Ctrl` + `K`** 或 **`/`**（焦点不在输入框时）触发同样效果。
4. 输入站点/分组关键词 → 出现下拉结果；`↑` / `↓` 选择，`Enter` 跳转，`Esc` 关闭。
   - 若 ⌘K 无反应：先点一下页面任意处，确保焦点在页面内（焦点停留在浏览器
     地址栏时属于浏览器原语，页面事件收不到，无法拦截）。

> 双实例说明：移动端抽屉里的搜索框副本不响应快捷键
> （`listenGlobalShortcut={!isStatic}`），避免两个输入框同时抢焦点。

## 2. 侧栏 / 搜索跳转（虚拟化滚动）

1. 保持「全部」视图（顶部无 Housemap 图标高亮，即未选中分组）。
2. 确认数据量足够大（Mock 数据几百个分组时可参考；真实 D1 数据更佳）。
3. 找一个位于列表**很靠下方**的分组：
   - 左侧侧栏点击它 → 页面应平滑切换为该分组的单组视图，无空白帧、无跳闪。
   - 或 ⌘K 搜索该分组名 / 其中某个站点 → Enter 后同样跳转。
4. 点 TopBar 的「回到全部」（房子图标）→ 回到虚拟化全部视图并滚回顶部。

> 虚拟化是否生效（可选验证）：全部视图下打开 DevTools →
> Elements 面板，搜索 `role="listitem"` 或 `data-index`，
> 挂载的分组卡片数量应远小于分组总数（只渲染视口附近 ± 3 行）。

## 3. 折叠展开高度重测

1. 全部视图滚动到含较多站点的分组。
2. 点分组的折叠按钮把它收起来 → 下方内容应立即上移、无残留空白或重叠。
3. 再点展开 → 下方内容下移铺开，滚动位置不会跳动错位。
4. 连续折叠/展开多个分组验证高度链稳定。

> 原理：`@tanstack/react-virtual` 用 `ResizeObserver` 自动测量每个行的真实高度，
> 折叠/展开触发的尺寸变化会被实时吸收并重排。

## 4. 本地收藏置顶（访客与管理员账号都可用）

1. **访客（浏览）模式**：鼠标移到站点卡片，点右侧星标（黄色即已收藏）。
2. **管理员（编辑）模式**：星标同样显示；星标按下时已拦截 pointerdown，
   不会触发站点的拖拽排序，可放心点击。
3. 收藏后该站点会立刻在该分组内置顶显示（其余站点保持原顺序）。
4. 刷新页面（`⌘R`）→ 收藏与置顶状态保留（存于 `localStorage['favoriteSites']`）。
5. 再点星标取消收藏 → 恢复原顺序。
6. 收藏是纯本地的：不落 D1、不影响其他访客/管理员数据。

## 5. 开发者选项（设置里开关，无需改源码）

路径：TopBar 右上「⋯」→ **个性化设置** → **开发者** 页签。

1. **帧率监测面板（FPS）**：打开后右下角实时显示 FPS / 最低帧 / 均值 /
   长任务 / 内存；`Shift+P` 可随时隐藏或再显示面板。
   - 开发模式（`pnpm dev`）默认开启，生产构建默认关闭。
2. **调试日志面板**：打开后捕获页面 console 输出与 JS 报错，右下角浮层
   实时查看（可最小化 / 清空），不打开 DevTools 也能快速定位问题。
3. 两个开关仅作用于当前浏览器（`localStorage['navihive_dev_options']`），
   只影响本机诊断，不会写入 D1 全局配置，也不影响其他访客/管理员账号。

## 7. 内置毛玻璃拟态（默认开启，无需粘贴 CSS）【新增】

1. 打开页面（默认 Mock API），确认**无需任何配置自动生效**：
   - 站点卡片/分组卡片为半透明玻璃质感，暗色下白字带阴影；
   - 侧边栏、对话框、下拉菜单同样半透明（浮层更实一些保证可读）。
2. 验证开关可控：TopBar「⋯」→ **个性化设置** → **动态效果** → 关闭「毛玻璃效果」→
   保存后卡片立即恢复不透明令牌色；重新打开开关恢复玻璃质感。
3. 验证深浅主题自适应：切换亮/暗主题（TopBar 主题按钮），玻璃效果两种模式下都可读
   （暗 = 白字白玻璃；亮 = 深字亮玻璃）。
4. 数据默认：即使清除「自定义 CSS」输入框内容，毛玻璃效果仍在（已内置为
   `site.glassEffect` 默认开启，不再依赖手写那段 CSS）。
5. （可选）若你的站点此前在「自定义 CSS」里粘贴过同样的毛玻璃代码，可清空该字段，
   效果由内置样式接管，避免重复叠加。

> 性能说明：backdrop-filter 在书签非常多时可能影响滚动帧率；
> 内置开关关闭后立即回退为不透明样式，用作兜底。

## 6. 常见问题

| 现象 | 检查 |
| --- | --- |
| 全部视图一片空白 | 确认 `group` 数据已加载（页面有骨架屏）；分组数为 0 时高度也为 0 |
| 跳转位置偏上被 TopBar 盖住 | 预期已避开：`scrollPaddingStart=56`（TopBar 48 + 冗余 8） |
| 分组卡片位置错位 | 一般是窗口 resize 或顶部元素动态变化后 `scrollMargin` 过期，重新滚动即可触发重测 |
| ⌘K 无反应 | 先点页面任意处把焦点还给页面再按；浏览器扩展（如 Vimium）可能抢占 |
| 管理员看不到收藏星标 | 已修复：编辑模式星标同样显示，且拦截 DnD 不会误拖拽 |
| 开发者页签不存在 | 确认 `pnpm dev` 运行的是最新代码（HMR 或刷新后生效） |
